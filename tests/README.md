# Testing DFIP

Four layers, from fastest to most complete. Everything runs in Docker; no local Python is needed.

| Layer | What it proves | Command (from the repository root) | Time |
|---|---|---|---|
| Unit | Parsers (fls bodyfile, mmls, setupapi, SYSTEM hive, browser databases), hashing, E01 working copies | `docker run --rm -v "$PWD/backend:/src" -w /src dfip-backend python -m pytest -q` | seconds |
| System (API) | Every API area against ground truth, on a throwaway stack | `sh tests/system/run.sh` | ~2 min |
| UI | The web portal and the desktop UI build in a real browser | `sh tests/ui/run.sh` | ~5 min |
| Desktop app | The installed Windows app (native hashing, workstation, sign-in) | see below | manual |

Before the system and UI layers: build the images (`docker compose build`) and the synthetic test disk:

```bash
docker run --rm -v "$PWD:/repo" -w /repo python:3.11-slim sh scripts/test-image/make-test-image.sh
```

## System tests (`tests/system`)

`run.sh` starts an isolated copy of the stack (`compose.yml`: its own MongoDB, Redis and storage volume, no host ports), runs `dfip_full_test.py` inside the backend container, then removes the stack. Nothing in a running DFIP is touched.

Results are checked against ground truth that does not come from DFIP: the known contents of the test disk (`scripts/test-image/make_artifacts.py`; the deleted payroll export is regenerated byte for byte), and Sleuth Kit (`mmls`, `fls`, `icat`, `mactime`) and regipy run directly on the image.

| Phase | Covers |
|---|---|
| `main` (backend in its default configuration) | health, authentication (tokens, refresh rotation, logout, password change), approval-mode sign-up, cases and case isolation, roles, evidence upload and preservation, the analysis job, file index, deleted-file recovery, timeline, browser history, USB history, indicators, carving, search, findings, analyst assignment, reports, chain of custody, audit log, notifications, administration, the desktop workstation API (including offline sync), live events, threat intelligence, E01 support, bad images, cancelling, overview counts, evidence tampering and audit-log tampering |
| `desktop_writes` | `REQUIRE_DESKTOP_FOR_WRITES=true`: the web is read-only, a registered workstation can write |
| `reg_open`, `reg_disabled` | `REGISTRATION_MODE=open` and `disabled` |
| PDF (`check_pdf.py`) | the text of generated reports: all 12 sections, hashes, custody, findings, literal markup, a tampered-evidence report |

Logs and JSON results are in `tests/system/out/`.

## UI tests (`tests/ui`)

`run.sh` runs the Playwright suites against the stack on `http://localhost` (as `host.docker.internal` from the test container). They create their own cases and users in that stack.

| Suite | Covers |
|---|---|
| `ui_e2e` | website, sign-in, new case, upload, analysis, evidence detail, deleted files and recovery, timeline (zoom), browser, USB, indicators, search, findings, reports, custody, carving, audit and system pages, sign-out |
| `ui_desktop` | the desktop build (`frontend/dist-desktop`): opens on sign-in, server address, workstation registration |
| `ui_roles` | what each role sees and can do |
| `ui_download` | installer links on the website, sign-in page and workspace; downloaded file matches its SHA-256 (needs a published installer) |
| `ui_auth` | create account, approval, rejection, disabled accounts |
| `ui_signout` | sign-out at different window widths |
| `ui_extra` | keyboard sign-in, UTC/local times, case editing and switching, top-bar search, user administration, password change, invalid sessions, 1024 and 1280 px windows |

`outage.sh` (separate, because it **stops the backend container** for about a minute) checks that the UI explains an outage, keeps the session, and continues once the API is back.

## Desktop app

Install the published setup (`storage/downloads/*_x64-setup.exe`), then start it with remote debugging and drive it with Playwright over CDP:

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = '--remote-debugging-port=9333'
& "$env:LOCALAPPDATA\DFIP Investigator\dfip-investigator.exe"
```

Check: the app opens on sign-in on every launch; the workstation panel shows the host; "Verify a local copy" on an evidence item reports a match for the same image file; Change password opens; sign-out returns to the sign-in page.
