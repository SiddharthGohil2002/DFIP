# API

OpenAPI is exposed automatically by FastAPI at `/docs` and `/openapi.json`.

Core route groups: `/api/auth`, `/api/cases`, `/api/evidence`, `/api/forensics`, `/api/jobs`, `/api/findings`, `/api/comments`, `/api/physical`, `/api/tags`, `/api/chain`, `/api/notifications`, `/api/reports`, `/api/exports`, `/api/admin`, `/api/desktop`, plus `/ws`.

Recent additions:

| Route | Purpose |
|---|---|
| `POST /api/jobs/analysis/{id}` (optional body `{profile: quick\|standard\|full}` or `{modules: [...]}`) | Queue an analysis; no body = standard. 400 for an unknown profile or module, 409 while another analysis of the evidence is queued or running |
| `PUT /api/evidence/{id}/time-zone` (body `{zone: IANA name\|UTC\|null, reason}`) | Set the computer's time zone by hand (null: back to the SYSTEM hive's) and re-index; audited |
| `GET /api/forensics/computer?case_id&evidence_id` | Per evidence: computer name, Windows version, network, last shutdown, time zone and user accounts |
| `GET /api/jobs/analysis/modules` | The analysis modules (name, label, description, requirements, version) and profiles |
| `GET /api/forensics/evidence/{id}/files?category&renamed&encrypted&hash_status&hide_known&sha256` | File index filters: real type category, renamed (content contradicts the name), encrypted, hash-set status (`KNOWN_BAD`, `NOTABLE`, `KNOWN_GOOD`), hide known-good files, one SHA-256. Entries carry `md5`, `sha1`, `sha256`, `mime`, `magic`, `file_category`, `ext_mismatch`, `expected_type`, `entropy`, `encryption`, `hash_status`, `hash_sets` |
| `GET /api/forensics/content-search?case_id&q&mode=text\|regex&evidence_id&skip&limit` | Files whose text contains `q` (case-insensitive, 3+ characters) or matches the RE2 regular expression `q`; first 20 matches per file with snippet, byte offset and length; evidence without a content index is listed in `not_indexed`; `complete` is false when the 15 s limit was reached. 400 for a short term or an invalid pattern. Audited |
| `GET /api/forensics/entities?case_id&kind&q&evidence_id` | Found data: one row per value per evidence item (card and Aadhaar numbers without `value`), count per kind, which evidence has been analysed |
| `GET /api/forensics/entities/{id}`, `POST /api/forensics/entities/{id}/reveal` | One found value with its occurrences (file, byte offset); the full value of a masked number (audited) |
| `GET /api/forensics/evidence/{id}/files?members=true` | Files taken out of archives and documents (each with `container`: kind, parent, member, depth, encrypted, note); without it, only file-system files |
| `GET /api/forensics/members/{entry_id}/content\|preview\|raw`, `POST /api/forensics/members/{entry_id}/recover` | View an archive member (409 when it was not extracted), or recover it as a hashed, custody-logged file |
| `GET /api/forensics/evidence/{id}/volume?volume_id&start&length` | Raw bytes of a volume at a byte offset (unallocated-space hits); every page is audited |
| `GET /api/forensics/registry?case_id&type&search&user&flagged&evidence_id` | Registry records of one kind: USERASSIST, SHELLBAG, TYPED_PATH, TYPED_URL, EXPLORER_SEARCH, RECENT_DOC, RUN_MRU, PERSISTENCE (with `flags`), INSTALLED_PROGRAM, AMCACHE_FILE, SHIMCACHE_ENTRY, BAM_ENTRY, RDP_CONNECTION, NETWORK_DRIVE |
| `GET /api/forensics/registry/hives?case_id` | The hives read per evidence item: path, kind, user and SID, SHA-256, transaction logs and whether the hive was dirty |
| `GET /api/forensics/execution?case_id&search&ran&evidence_id` | Execution evidence: one row per program with its Prefetch, UserAssist, BAM, Amcache and ShimCache traces |
| `GET /api/forensics/eventlogs/logs?case_id&evidence_id` | The event logs read per evidence item: path, channel, records, recovered records, first and last event, SHA-256, size, and whether the log was not closed cleanly, full, damaged or capped |
| `GET /api/forensics/eventlogs/events?case_id&evidence_id&notable&channel&event_id&category&level&user&search&start&end&detection&recovered&order&skip&limit` | Event records, oldest first. `event_id` takes a comma-separated list (at most 50); `level` is `critical`, `error` or `warning` (or worse); `search` matches the description and every data value; `detection` a rule ID. Records carry the System fields, `data`, `data_values`, `user_data`, `details` (classic PowerShell key=value lines, `DecodedCommand`), `category`, `title`, `description`, `user`, `notable`, `detections`, `recovered`. 400 for a bad filter |
| `GET /api/forensics/eventlogs/events/{id}?case_id` | One record with its XML as libevtx rendered it |
| `GET /api/forensics/eventlogs/detections?case_id&evidence_id` | Detections, most severe first: rule ID, title, level, description, ATT&CK tags, false positives, count, first and last time, the group of a counting rule, the matched records' keys and an example |
| `GET /api/forensics/user-activity?case_id&type&search&user&file_state&evidence_id&skip&limit` | Records of one kind: JUMPLIST_ENTRY, TIMELINE_ACTIVITY, THUMBNAIL (view the picture through `/api/forensics/artifacts/{artifact_id}/raw` or `/preview`), SRUM_NETWORK, SRUM_APP_USAGE, SRUM_CONNECTIVITY, SEARCH_INDEX_ENTRY. `file_state` (search index entries, and thumbnails by their indexed file): `on disk`, `deleted`, `not on the disk` |
| `GET /api/forensics/user-activity/network?case_id&evidence_id` | SRUM network usage per application and user: bytes sent and received, hours recorded, first and last, network types |
| `GET /api/forensics/ntfs/volumes?case_id` | NTFS volumes read: serial number, label, MFT entries, journal records |
| `GET /api/forensics/ntfs/timestomp?case_id&evidence_id&level&search&skip&limit` | Files whose times look altered: `level` strong or possible, the `$SI` and `$FN` times and the reasons |
| `GET /api/forensics/ntfs/streams?case_id&evidence_id&downloaded&search&skip&limit` | Alternate data streams: path, size, SHA-256, text preview, `zone` (Zone.Identifier: ZoneId, ZoneName, HostUrl, ReferrerUrl), the file-index `inode` for the viewer; `downloaded=true` for Zone.Identifier streams only |
| `GET /api/forensics/ntfs/usn?case_id&evidence_id&search&reason&entry&start&end&closing&order&skip&limit` | USN journal records in journal order: time, MFT entry and sequence, parent, name, resolved path, reasons. `reason` takes one reason name (400 for others); `closing=true` lists only closing records |
| `GET /api/forensics/browser?case_id&kind&evidence_id&browser&user&search&recovered&skip&limit` | Browser records of one kind: `BROWSER_HISTORY`, `BROWSER_DOWNLOAD`, `BROWSER_SEARCH`, `BROWSER_COOKIE`, `BROWSER_BOOKMARK`, `BROWSER_AUTOFILL`, `BROWSER_LOGIN` (site and user name, never a password), `BROWSER_RECOVERED` (deleted history rows: `recovered_from`, `page`, `file`, `file_offset`, `wal_frame`, `row_id`, `previous_version`); `recovered=true` lists searches from deleted rows |
| `GET /api/forensics/email/stores?case_id` | Mailboxes read: path, format (PST, OST, MBOX, THUNDERBIRD, EML/MSG), client, user, size, SHA-256, messages, attachments, deleted messages, folders, read errors |
| `GET /api/forensics/email/messages?case_id&evidence_id&store&folder&search&address&attachments&deleted&direction&start&end&order&skip&limit` | Messages without bodies: sender, recipients, sent and received times, folder, direction, flags, attachment names, snippet. `search` covers subject, people, attachment names and text; `address` a sender or recipient; `direction` sent or received (400 otherwise) |
| `GET /api/forensics/email/messages/{id}` | One message: text body, transport headers, recipients, attachments with the file-index entry (`entry_id`) that opens each in the file viewer. Audited (`EMAIL_VIEWED`) |
| `GET /api/forensics/email/messages/{id}/html` | The HTML body with inline pictures as `data:` URIs (up to 4 MiB) and `remote_references` (never loaded). The caller sanitises it before display. Audited |
| `GET /api/forensics/chat-cloud?case_id&type&evidence_id&user&provider&conversation&files_only&search&skip&limit` | Chat and cloud records of one type: `CHAT_ACCOUNT`, `CHAT_CONTACT`, `CHAT_MESSAGE`, `CHAT_CALL`, `CHAT_FILE_TRANSFER`, `CHAT_APP` (detected apps, with `parsed` and `reason`), `CLOUD_ACCOUNT`, `CLOUD_FILE` (with `hash`, `hash_algorithm` and `same_content`: files on the evidence with the same SHA-1) |
| `GET /api/forensics/chat-cloud/conversations?case_id&evidence_id` | Chat conversations with their message counts and first and last message times |
| `GET /api/forensics/media?case_id&evidence_id&kind&gps&camera&deleted&source&text&search&skip&limit` | Pictures and videos (newest taken first): `kind` picture or video, `gps=true` with a location, `source` disk, archive or email, `text=true` with OCR text; each with `media` (size, format, camera, `exif`, `gps`, `taken`, `taken_local`, `taken_basis`, `video`, `frames`, `thumb`) |
| `GET /api/forensics/media/cameras?case_id` | Cameras with how many items each took, and the first and last time |
| `GET /api/forensics/media/locations?case_id&evidence_id` | Every picture and video with a GPS location |
| `GET /api/forensics/media/{entry_id}` | One item with all its metadata and the full OCR text |
| `GET /api/forensics/media/{entry_id}/thumb?frame` | The thumbnail (or keyframe `frame`) DFIP made, as a JPEG with `nosniff`, `attachment` and a sandbox CSP; audited (`FILE_CONTENT_VIEWED`, view `thumbnail` or `keyframe n`) |
| `GET /api/forensics/executables?case_id&evidence_id&flagged&signature&search&skip&limit` | Programs, those that stand out most first (without sections and imports): `flagged=true` score 3 or more, `signature` valid, untrusted, expired, invalid, unsigned or error, `search` path, version information, signer or SHA-256 |
| `GET /api/forensics/executables/{artifact_id}` | One program: `pe` (sections, imports, version information, compile time, imphash), `signature` (status, signers and their chains), `api_groups`, `flags`, `score`, `capa`, `vt` |
| `POST /api/forensics/executables/{artifact_id}/capa` | Runs capa on the program now (`ANALYSIS_RUN`) and keeps the result with who asked; audited (`CAPA_RUN`) |
| `PUT /api/cases/{case_id}/threat-intel` (body `{auto_lookup}`) | Turns automatic VirusTotal lookups of program hashes on or off for the case (`CASE_UPDATE`; audited `THREAT_INTEL_AUTO_LOOKUP_SET`); turning them on starts a `reputation` run per analysed evidence item (`jobs`), `key_configured` says whether a key is set |
| `GET /api/malware/status` | What the scanners use: DFIP's YARA rules and the rule sets, ClamAV databases, whether capa is installed, whether a VirusTotal key is set and its rate |

| `PATCH /api/malware/yara/{set_id}` (body `{enabled}`), `DELETE /api/malware/yara/{set_id}` | Turn a set off or on, or delete it (`RULES_MANAGE`); both rescan |
| `GET /api/malware/clamav`, `POST /api/malware/clamav` (multipart `file`), `DELETE /api/malware/clamav/{name}` | ClamAV database files with their version and signature count; an added file must load in clamscan (400 otherwise) and replaces one of the same name; both rescan (`RULES_MANAGE`) |
| `POST /api/malware/clamav/update` | Downloads the official ClamAV databases with freshclam as a `CLAMAV_UPDATE` job (`RULES_MANAGE`; needs internet access), then rescans |
| `GET /api/forensics/user-activity/files?case_id` | The Jump List, Timeline, thumbnail cache, SRUM and search index files read, with their SHA-256 |
| `GET /api/forensics/eventlogs/facets?case_id&evidence_id` | Channels, categories, event IDs and users with their record counts (for the filters) |
| `GET /api/forensics/hash?case_id&digest` | Every file in the case with this MD5, SHA-1 or SHA-256, and recovered, carved and extracted copies with this SHA-256; 400 if the value is not a hash |
| `GET /api/forensics/flagged?case_id&kind=renamed\|encrypted\|known_bad\|notable` | Flagged files of the case |
| `GET /api/hashsets` | Imported hash sets (every signed-in user): kind, status, format, counts per algorithm, invalid lines, source file and SHA-256 |
| `POST /api/hashsets` (multipart `file`, `name`, `kind`, `description`) | Import a hash set from an upload (`HASHSET_MANAGE`); queues a `HASHSET_IMPORT` job, then re-matches every processed evidence item |
| `GET /api/hashsets/incoming`, `POST /api/hashsets/import-local` (body `{filename, name, kind, description}`) | Large sets placed in `storage/hashsets/incoming` on the server: list and import by name (no folders) |

| `POST /api/evidence/upload` (multipart `case_id`, one or more `file`, `sha512`) | One disk image: a file, or the files that are one image together (EnCase segments, split parts, a virtual disk with its parents); 400 with what is missing when a set is incomplete. Text starting with `=`, `+`, `-`, `@`, a tab or a carriage return gets a leading apostrophe and XLSX cells are never formulas.
