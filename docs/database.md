# MongoDB

Collections: users, roles, cases, evidence, fs_entries, forensic_artifacts, timeline_events, usb_artifacts, patterns, anomalies, findings, comments, physical_items, ai_requests, settings, retention_runs, tags, reports, chain_of_custody, audit_logs, notifications, jobs, job_sequences, desktop_devices, refresh_tokens, analysis_facts, pipeline_warnings, hash_sets, entities, event_records, usn_records, email_messages.

- `forensic_artifacts` also holds the Windows activity records (`PROGRAM_RUN`, `RECENT_FILE`, `RECYCLE_BIN_ITEM`), one `COMPUTER_INFO` per evidence (computer name, OS, interfaces, last shutdown, time zone, hives with SHA-256) and the `USER_ACCOUNT` records (SID, RID, user name, full name, logon statistics, profile path, source `SAM` or `PROFILE_LIST`).
- `evidence.time_zone_override`: `{zone, reason, set_by(_name), set_at}` when an investigator set the computer's time zone; `fs_entries` on FAT volumes carry `time_zone` and `atime_date_only`.
- Pipeline output (`fs_entries`, `timeline_events`, `forensic_artifacts`, `usb_artifacts`, `pipeline_warnings`) carries `pipeline: true`, `pipeline_module` (the analysis module that wrote it), `module_run_id` and `analysis_job_id`; each module replaces only its own documents (index on `evidence_id, pipeline_module`).
- `fs_entries` and `FILE_MACB` events carry `volume_id` (`p<start sector>`) next to `partition_offset`. Other timeline events carry `nk`, a stable natural key used to re-link tags.
- `evidence.modules.<name>`: `{status, job_id, run_id, version, counts, warnings, warnings_total, error, started_at, finished_at}` for each analysis module's latest run; `evidence.analysis_summary` merges the counts.
- `fs_entries` after file processing: `md5`, `sha1`, `sha256`, `mime`, `magic` (libmagic description), `file_category`, `ext_mismatch`, `expected_type`, `entropy`, `encryption` (`{kind: ZIP|OFFICE|PDF|HIGH_ENTROPY, detail}` or null), `hash_basis`, `hash_error` (module `fileproc`), and `hash_status` (`KNOWN_BAD|NOTABLE|KNOWN_GOOD`) and `hash_sets` (`[{set_id, name, kind, algorithm}]`, module `hash_match`). Indexes on `(evidence_id, sha256)`, `(case_id, sha256)` and `(evidence_id, file_category)`.
- `fs_entries` for archive members (module `containers`): path `<container path>!/<member>`, `container` = {kind (zip, ooxml, odf, ole, pdf, 7z), parent, member, depth, encrypted, packed_size, modified, store, note}; containers carry `archive` = {kind, members, extracted, encrypted, not_extracted, names_encrypted}. Extracted members are stored under generated names in `storage/analysis/members/<EVID>/`.
- `forensic_artifacts` from the registry (module `registry`, `source: REGISTRY`): types USERASSIST, SHELLBAG, TYPED_PATH, TYPED_URL, EXPLORER_SEARCH, RECENT_DOC, RUN_MRU, PERSISTENCE, INSTALLED_PROGRAM, AMCACHE_FILE, SHIMCACHE_ENTRY, BAM_ENTRY, RDP_CONNECTION, NETWORK_DRIVE, each with `hive`, `user`, `sid`, `key_last_write` and a natural key `nk` (used by tags of item type REGISTRY).
- `event_records` (module `eventlogs`): one document per event log record: `log`, `log_path`, `channel`, `provider`, `provider_guid`, `event_id`, `qualifiers`, `version`, `level`, `level_name`, `task`, `opcode`, `keywords`, `time`, `record_id`, `computer`, `user_sid`, `user`, `process_id`, `thread_id`, `data` (EventData / flattened UserData, field names without dots), `data_values` (unnamed values), `user_data`, `details`, `category`, `title`, `description`, `timeline_type`, `notable`, `detections`, `recovered`, `truncated`, `parse_error`, `xml` (at most 32,768 characters), `text` (for search) and a natural key `nk` (used by tags of item type EVENT). Indexes on `(case_id, time)`, `(case_id, notable, time)`, `(case_id, event_id, time)`, `(case_id, channel, time)` and `(evidence_id, nk)`.
- `forensic_artifacts` from module `browser_depth`: `BROWSER_SEARCH` (`term`, `engine`, `url`, `time`, `source_table`, `row_id`, `recovered`, `recovered_from`), `BROWSER_COOKIE` (`host`, `name`, `path`, `value` or `value_encrypted`, `created`, `expires`, `last_accessed`, `secure`, `http_only`, `persistent`), `BROWSER_BOOKMARK` (`title`, `url`, `folder`, `added`), `BROWSER_AUTOFILL` (`field`, `value`, `kind`, `times_used`, `first_used`, `last_used`), `BROWSER_LOGIN` (`site`, `action_url`, `username`, `username_encrypted`, `password_saved`, `never_save`, `created`, `last_used`, `times_used`; never a password) and `BROWSER_RECOVERED` (`url`, `title`, `visit_count`, `last_visit_time`, `recovered_from`, `page`, `file`, `file_offset`, `wal_frame`, `previous_version`, `source_table`, `row_id`), each with `browser`, `user`, `profile`, `source_path` and `nk` (tags of item type BROWSER).
- `email_messages` (module `email`): `store_path`, `store_format`, `user`, `folder`, `number`, `message_id`, `subject`, `from_name`, `from_address`, `to`/`cc`/`bcc`/`reply_to` (`[{name, address}]`), `sent`, `received`, `time`, `direction`, `deleted`, `flags`, `body_text`, `body_html`, `headers`, `truncated`, `has_html`, `snippet`, `attachment_count`, `attachments` (`name`, `size`, `mime`, `content_id`, `inline`, `sha256`, `store`, `entry_path`), `originating_ip`, `in_reply_to`, `nk` (tags of item type EMAIL); indexes on `(case_id, time)`, `(evidence_id, nk)` and `(case_id, store_path, folder, time)`. `forensic_artifacts` `EMAIL_STORE` per mailbox (`path`, `format`, `client`, `user`, `size`, `sha256`, `messages`, `attachments`, `deleted_messages`, `folders`, `errors`). Attachments are `fs_entries` members with `container.kind` `email` and `container.message_nk`.
- `fs_entries.media` (module `media`): `kind` (picture or video), `width`, `height`, `format`, `thumb`, `camera`, `exif` (the fields shown), `gps` (`lat`, `lon`, `alt`), `taken` (UTC), `taken_local`, `taken_basis`, `video` (`duration`, `video_codec`, `audio_codec`, `frame_rate`, `container`, `encoder`, `location`, `recorded`), `frames` (`time`, `file`, `method`), `error`. Index on `(evidence_id, media.kind, media.taken)`. `fs_entries.ocr` (module `ocr`): `text`, `chars`, `pages`, `engine`, `language`.
- `forensic_artifacts` from module `chat_cloud`: `CHAT_ACCOUNT`, `CHAT_CONTACT`, `CHAT_MESSAGE` (`time`, `author`, `author_name`, `conversation`, `partner`, `kind`, `text`), `CHAT_CALL` (`time`, `duration_seconds`, `incoming`, `members`), `CHAT_FILE_TRANSFER` (`direction`, `partner`, `status`, `file_name`, `file_path`, `size`, `started`, `finished`), `CHAT_APP` (`app`, `user`, `path`, `parsed`, `reason`, `files`, `size`, `last_change`), `CLOUD_ACCOUNT` (`provider`, `account`, `sync_folder`, `web_url`, `files`) and `CLOUD_FILE` (`provider`, `account`, `path`, `is_folder`, `size`, `modified`, `hash`, `hash_algorithm`, `same_content`, `local_path`), each with `user`, `source_path` and `nk` (tags of item type CHAT_CLOUD). `fs_entries` gains an index on `(evidence_id, sha1)`.
- `forensic_artifacts` from module `ntfs`: `TIMESTOMP_SUSPECT` (`level`, `reasons`, `path`, `entry`, `sequence`, `allocated`, `si_created`, `si_modified`, `si_changed`, `si_accessed`, `fn_created`, `fn_modified`, `fn_changed`, `fn_accessed`) and `ALTERNATE_STREAM` (`path`, `file_path`, `stream`, `size`, `sha256`, `text`, `kind`, `zone`, `entry`, `inode`), with `volume_id` and a natural key `nk` (tags of item type WINDOWS). `usn_records` (module `ntfs`): `usn`, `time`, `entry`, `sequence`, `parent_entry`, `parent_sequence`, `name`, `path`, `reasons`, `reason_flags`, `file_attributes`, `version`, `source_info`, `volume_id` and `nk` (tags of item type USN); indexes on `(case_id, time)`, `(evidence_id, entry, usn)` and `(evidence_id, nk)`.
- `forensic_artifacts` from module `user_activity`: `JUMPLIST_ENTRY` (`app_id`, `application`, `jumplist_kind`, `category`, `target`, `destlist_path`, `entry_number`, `last_used`, `pinned`, `pin_position`, `access_count`, `hostname`, droid identifiers, `mac_address`, `lnk`), `TIMELINE_ACTIVITY` (`table`, `activity_type`, `activity_label`, `app`, `app_display_name`, `display_text`, `description`, `content_uri`, `start_time`, `end_time`, `duration_seconds`, `clipboard_text`, `operation_type`), `THUMBNAIL` (`entry_hash`, `width`, `height`, `image_type`, `sha256`, `path` to the stored picture, `indexed_path`, `indexed_file_state`), `SRUM_NETWORK`, `SRUM_APP_USAGE`, `SRUM_CONNECTIVITY` (`time`, `app`, `sid`, `user`, bytes and times) and `SEARCH_INDEX_ENTRY` (`path`, `size`, times, `owner`, `kind`, `summary`, `thumbnail_cache_id`, `file_state`), each with a natural key `nk` (tags of item type WINDOWS). Thumbnails are stored under `storage/analysis/thumbs/<EVID>/<run>/<sha256>.<ext>`.
- `forensic_artifacts` of type `EVENTLOG_DETECTION` (module `eventlogs`): rule ID, title, level, description, tags, references, false positives, rule file, aggregation, count, first, last, group, `record_nks` and `sample`. `usb_artifacts` gain `eventlog_events`, `eventlog_first_connected`, `eventlog_last_connected` and `eventlog_last_removed` (devices seen only in the event logs have `source: EVENT_LOG`).
- Unallocated space (module `unallocated`): `storage/analysis/text/<EVID>.unalloc.sqlite`, the same layout as the content index, with documents of method `unallocated` whose spans map text to volume byte offsets.
- `forensic_artifacts` of type `EXECUTABLE` (module `executables`): `path`, `name`, `entry_id`, `inode`, `deleted`, `container`, `size`, `md5`, `sha1`, `sha256`, `pe` (`machine`, `bits`, `dll`, `compiled`, `subsystem`, `entry_point`, `image_base`, `sections` with `entropy`, `imports` `{dll: [functions]}`, `import_count`, `imphash`, `version_info`, `pdb_path`, `has_signature`, `overlay_size`), `signature` (`status`, `detail`, `signers` with their `certificates`), `api_groups`, `flags` (`code`, `severity`, `label`, `detail`), `score`, `capa` (`status`, `version`, `capabilities` with `namespace`, `attack`, `mbc`, `matches`; `ran`), `vt` (module `reputation`: `status`, `malicious`, `suspicious`, `harmless`, `undetected`, `queried_at`, `from_cache`, `link`) and `nk`. Index on `(case_id, type, score)`. ClamAV detections are `MALWARE_INDICATOR` records with `source` and `engine` `CLAMAV`/`ClamAV`; YARA ones have `engine` YARA, `ruleset` and `ruleset_id`.
- `yara_rulesets`: one document per added rule set (`YR-0001`..., unique): name, description, rule names and count, SHA-256, size, `enabled`, who added it and when; the rules are in `storage/yara/<set_id>.yar`. ClamAV databases are files in `storage/clamav/` (no collection).
- `cases.threat_intel`: `{auto_lookup, set_by, set_by_name, set_at}`; automatic VirusTotal lookups are off when it is missing.
- `evidence` of more than one file: `image_set` (`kind` `segments`, `split` or `chain`, `count`, `label`) and `image_files` (`name`, `path`, `size`, `sha256`, `sha512`, `role`: `segment n`, `part n`, `disk`, `parent`, `extent of ...`), the evidence's `sha256`/`sha512` being over the files in order; `working_copy` gains `method` (`ewfexport`, `libvhdi`, `libvmdk`, `libqcow`, `concatenated`); a decrypted volume has `derived_from` (`evidence_id`, `volume_id`, `kind`, `method`, `key_id`, `source_sha256`, `job_id`) and `acquisition_status` `DERIVED`. Index on `derived_from.evidence_id`.
- `evidence` of format `LOGICAL` (a package of collected files): `package` (`archive`, `files`, `folders`, `links`, `skipped`, `bytes`, `roots` with `volume_id`, `path`, `os`, `label`, `manifest` and `manifest_sha256`, `zip_local_times`, `unpacked_at`); its `fs_entries` have `logical: true`, the package path as `inode`, `package_sha256` and, for plain ZIP times, `time_basis`. `fs_entries` of symbolic links (disk images) have `link_target`; APFS entries have `volume_id` `p<start>/apfs<block>`.
- `forensic_artifacts` from module `unix`: `COMPUTER_INFO` and `USER_ACCOUNT` with `os_family` (`uid`, `gid`, `shell`, `groups`, `admin`, `password_state`, `password_last_set`, `flags`), `SHELL_COMMAND` (`user`, `shell`, `order`, `command`, `time`, `flags`, `notable`), `UNIX_EVENT` (`kind`, `label`, `log`, `time`, `user`, `ip`, `host`, `terminal`, `logout`, `duration_seconds`, `fields`, `summary`, `text`, `notable`), `SCHEDULED_JOB` (`mechanism`: cron, systemd, launchd or ssh key; `name`, `command`, `schedule`, `user`, `enabled`, `flags`, `notable`), `RECENT_DOCUMENT`, `QUARANTINE_EVENT`, `WIFI_NETWORK`, and Safari `BROWSER_HISTORY`/`BROWSER_DOWNLOAD` (`browser` Safari); each with `os_family`, `volume_id`, `source_path` and `nk`.
- `forensic_artifacts` from module `network` (each with `source` `TSHARK` and `nk`): `CAPTURE_INFO` (`file_type`, `encapsulation`, `packets`, `bytes`, `first`, `last`, `conversations`), `NET_CONVERSATION` (`protocol`, `client`, `client_port`, `server`, `server_port`, `packets`, `bytes`, `bytes_from_client`, `bytes_from_server`, `first`, `last`, `protocols`, `server_names`), `DNS_QUERY` (`time`, `client`, `server`, `name`, `query_type`, `answers`, `rcode`, `answered`), `HTTP_REQUEST` (`frame`, `time`, `client`, `server`, `server_port`, `stream`, `method`, `host`, `uri`, `url`, `user_agent`, `content_type`, `content_length`, `response_code`, `response_type`, `response_length`, `files` with `direction`, `name`, `path`, `sha256`, `size`, `content_type`, `part`), `TLS_HANDSHAKE` (`time`, `client`, `server`, `server_port`, `server_name`, `version`). The files HTTP carried are `fs_entries` with `volume_id` `capture` and `container.kind` `capture` (`store` under `members/capture/<EVID>/<sha256>`). Evidence of format `PCAP` is a capture.
- `forensic_artifacts` from module `phone` (each with `source` `PHONE`, `platform` and `os_family` Android or iOS, `volume_id`, `source_path` and `nk`): `PHONE_DEVICE` (`manufacturer`, `model`, `brand`, `os_version`, `build`, `security_patch`, `fingerprint`, `name`, `time_zone`, and counts: `messages`, `whatsapp_messages`, `calls`, `contacts`, `apps`, `system_apps`, `wifi_networks`), `PHONE_MESSAGE` (`app` SMS, MMS, iMessage, RCS or WhatsApp; `time`, `direction`, `party`, `party_name`, `chat_name`, `group`, `sender`, `sender_name`, `text`, `status`, `read`, `message_type`, `attachments` with `name`, `mime_type`, `size`, `device_path` and, when found in the extraction, `file` {`path`, `inode`, `volume_id`}), `PHONE_CALL` (`time`, `party`, `party_name`, `direction`, `duration`, `kind`, `app`, `location`, `country`), `PHONE_CONTACT` (`name`, `organization`, `numbers`, `emails`, `whatsapp_id`, `source`), `PHONE_APP` (`app_id`, `name`, `version`, `installed`, `updated`, `installer`, `path`, `category`, `notable`), `PHONE_WIFI` (`ssid`, `security`, `hidden`, `router_mac`, `added`, `last_joined`; never a password).
- `findings`: `status` (`DRAFT`, `IN_REVIEW`, `CHANGES_REQUESTED`, `APPROVED`; missing on older findings means draft), `version`, `created_by_name`, `reviewer_id`, `submitted_at`, `reviewed_by`, `reviewed_by_name`, `reviewed_at`, `approved_at` and `history` (`at`, `by`, `by_name`, `action`, `note`, `reason`, `changes` {field: [before, after]}).
- `comments`: `case_id`, `target_type` (`FINDING`, `TAG`, `FILE`, `EVIDENCE`), `target_id`, `target_label`, `text`, `mentions` (user IDs), `author_id`, `author_name`, `created_at`, `edited_at`, `previous` (earlier texts), `deleted`, `deleted_at`, `deleted_by_name`. Index on `(case_id, target_type, target_id, created_at)`.
- `cases` gain `member_ids`, `closed_at`, `retention` (`days`, `due_at`, `set_at`, `notified_at`), `ai_assist` (`enabled`, `set_by`, `set_by_name`, `set_at`) and, once deleted, `deleted`, `deleted_at`, `deleted_by(_name)`, `deletion_reason` (status `DELETED`; such cases are hidden everywhere but the retention page). `settings` holds `{_id: 'retention', enabled, days, set_by, set_by_name, set_at}`; `retention_runs` records each check (`at`, `due`, `held`, `notified`).
- `physical_items` (`PHY-0001` ..., unique): case, description, kind, make, model, serial number, bag and seal numbers, seizure (`seized_at`, `seized_from`, `seized_by`), `location`, `status` (`IN_STORAGE`, `CHECKED_OUT`, `RELEASED`, `DESTROYED`), `holder` (`person`, `since`, `purpose`), `evidence_ids`, `notes`, `photos` (`photo_id`, `sha256`, `size`, `mime`, `file`, `caption`, `name`, `added_by_name`, `added_at`; files under `storage/physical/<item>/`) and `custody` (`action` RECEIVED, CHECK_OUT, CHECK_IN, TRANSFER, RELEASE, DESTROY; `at`, `by_id`, `by_name`, `person`, `location`, `purpose`, `seal_intact`, `seal_number`, `notes`).
- `ai_requests` (`AI-00001` ...): case, user, time, `question`, `fact_ids`, `facts` (text and refs), `prompt` (exactly what was sent) and `prompt_sha256`, `status`, `answer`, `citations`, `unknown_citations`, `model`, `stop_reason`, `refusal_category`, `usage`, `anthropic_message_id`; failed requests keep `error`.
- `timeline_imports`: one document per imported timeline (`TI-0001`..., unique): case, evidence, file name, stored path, size, SHA-256, `format` (json_line or l2tcsv), `status`, `events`, `events_without_time`, `parsers`, `first`, `last`, `errors`, who imported it and when. Its events are `timeline_events` of type `PLASO_EVENT` with `import_id`, `import_line`, `parser`, `data_type`, `timestamp_desc`, `source_name`, `macb` (index on `import_id`).
- `volume_keys`: the key that unlocked an encrypted volume (`VK-0001`..., unique): evidence, volume, kind, method, `secret` (Fernet token; never returned by the API), who stored it and when, `use_count`, `last_used_at`, `derived_evidence_id`.
- `shadow_files` (module `shadow_copies`): `change` (`DELETED_SINCE`, `CHANGED_SINCE`, `ADDED_SINCE`), `path`, `name`, `is_dir`, `store`, `store_identifier`, `store_created`, `volume_id` (`p2048/vss1`), `parent_volume_id`, `partition_offset`, the snapshot's `inode`, `size`, `mtime`, `atime`, `ctime`, `crtime`, `current` (`entry_id`, `inode`, `size`, `mtime`) and `nk`. Indexes on `(evidence_id, volume_id, change, path)`, `(evidence_id, nk)`, `(case_id, change)`. `analysis_facts.shadow_copies.stores` lists each snapshot with its identifiers, creation time and counts.
- `hash_sets`: one document per imported set (`HS-0001`...): name, kind, description, status (`IMPORTING`, `READY`, `FAILED`), format, counts per algorithm, invalid lines, source file name, size and SHA-256, who imported it and when, the import job. The hashes themselves are not in MongoDB: each set is a read-only SQLite file in `storage/hashsets/<set id>.sqlite` (tables `md5`, `sha1`, `sha256`, raw digests as `WITHOUT ROWID` primary keys).
- `entities` (module `found_data`): one document per value per evidence item: `kind` (email, url, ip, phone, card, iban, crypto, aadhaar), `value` (normalised), `display` (as shown; masked for card and Aadhaar numbers), `sensitive`, `key` (SHA-256 of kind and value, used by tags), `details` (brand, country, scope, network), `count`, `file_count`, `occurrences` (up to 100: path, inode, volume, deleted, method, text and byte offset). Indexes on `(case_id, kind, value)` and `(evidence_id, kind, count)`.
- Content index (module `content`): not in MongoDB but one SQLite file per evidence in `storage/analysis/text/<EVID>.sqlite` (tables `docs` and the FTS5 `body`).
- `analysis_facts`: one document per evidence, `{evidence_id, <module>: {...}}`, with what one module tells the next (partitions, file systems, extracted artifacts).
- `pipeline_warnings`: every warning of every module run, `{evidence_id, case_id, message, created_at, pipeline_module, module_run_id}`.
- `jobs`: analysis jobs add `payload.profile` / `payload.modules`, and `worker`, `heartbeat_at`, `attempts` while a worker owns the job.
- `tags`: `{tag_id, case_id, evidence_id, item_type, item_id, match, key_hash, key_version, label, note, snapshot, created_by(_name), created_at}`; `match` is the item's natural key, so tags survive a re-analysis (unique on `case_id, item_type, key_hash`). Key version 2 uses `volume_id` and never a time that a time-zone correction could change; older tags are migrated at startup.
- `cases.legal_hold`: `{active, reason, set_by(_name), set_at, released_by(_name), released_at, release_reason}`, with every change appended to `cases.legal_hold_history`.

MongoDB is the source of truth. Evidence documents reference immutable original storage paths and SHA-256 acquisition hashes.
